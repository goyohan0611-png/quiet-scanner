1처음이면 이것부터

두 가지가 갖춰져야 스캔이 됩니다.

필요한 것확인 방법
관리자 권한 이 프로그램은 항상 관리자로 실행됩니다. 실행할 때 뜨는 창에서 예를 누르십시오. 격리(정적 ARP)와 원시 패킷 송신에 반드시 필요합니다.
Npcap 드라이버 설치할 때 없으면 받는 곳을 안내합니다. 나중에 필요하면 npcap.com 에서 받으십시오. 없으면 스캔이 아예 안 됩니다.

첫 화면에서 할 일

  1. 랜카드 확인지금 인터넷을 쓰고 있는 카드가 자동으로 잡힙니다. 현장 망에 따로 물렸으면 목록에서 직접 고르십시오.
  2. 대역 확인고른 카드의 대역이 자동으로 채워집니다. 192.168.0.0/24 같은 모양입니다. 다른 대역을 보려면 직접 고쳐 넣으십시오.
  3. 대역 스캔누르면 세 번에 걸쳐 훑습니다. 한 번 조용했다고 바로 "없음" 이라고 하지 않습니다.

2이 도구가 못 하는 것

이걸 먼저 아셔야 합니다. 도구를 잘못 믿으면 현장에서 사고가 납니다.

조용하다 ≠ 비어 있다

꺼져 있는 장비도 조용합니다. 빈 IP 목록은 "응답이 없던 주소"이지 "확실히 빈 주소"가 아닙니다. 야간에 꺼지는 장비가 있는 현장이면 특히 조심하십시오.

라우터 너머는 못 봅니다

충돌 탐지는 ARP로 합니다. ARP는 같은 대역(2계층) 안에서만 오갑니다. 라우터를 넘어가는 순간 아무것도 안 보입니다. 대형 현장을 한 자리에서 통째로 잡는 것은 이 방식으로 불가능합니다. 대역마다 가서 물려야 합니다.

단, 스위치 조회(SNMP)는 대역을 넘습니다. 다른 층 스위치 IP를 알면 거기 포트는 여기서 읽을 수 있습니다.

스캔이 안 끝났으면 빈 IP를 안 줍니다

중간에 멈추거나 오류가 나면 빈 IP 목록을 아예 내놓지 않습니다. 창에 이유가 뜹니다. 경고와 목록을 같이 주면 사람은 목록만 보기 때문입니다.

첫 방문에는 "속도 저하 없음"이 없습니다

속도 비교는 지난 기록이 있어야 합니다. 처음 온 현장은 비교할 것이 없으니 리포트에 '첫 기록'이라고 적힙니다. 이건 "확인했는데 문제 없음"이 아니라 "아직 모름"입니다.

3IP 충돌 정리하기

CCTV·AV 장비는 공장 초기 IP가 다 같습니다. 여덟 대를 물리면 여덟 대가 전부 같은 IP라고 우깁니다. 일반 스캐너는 그중 한 대만 봅니다 — 윈도우 ARP 표가 IP 하나당 MAC 하나만 저장하기 때문입니다.

이 도구는 전부 봅니다. 충돌난 줄은 빨갛게, 충돌 4대 같은 딱지가 붙습니다. 줄을 누르면 펼쳐집니다.

선을 안 뽑고 정리하는 순서

  1. 충돌 줄을 펼친다같은 IP를 쓰는 장비가 MAC별로 다 나옵니다.
  2. 한 대를 골라 오른쪽 클릭 → 이 장비만 격리그 IP를 그 MAC 하나에 못박습니다(정적 ARP). 이제 그 IP로 접속하면 그 한 대에만 붙습니다.
  3. 웹으로 들어가 IP를 바꾼다격리된 채로 장비 웹페이지를 열고 IP를 고칩니다. 새 IP는 후보 IP(Ctrl+F)에서 고르십시오.
  4. 격리를 푼다오른쪽 클릭 → 격리 해제. 다음 장비로 넘어갑니다.
격리를 걸어둔 채 프로그램을 끄지 마십시오

정적 ARP는 PC에 남습니다. 다음에 켜면 "남은 격리 N건"을 정리하겠다고 물어봅니다. 거기서 정리하시면 됩니다. 그냥 두면 그 IP는 계속 한 대로만 보입니다 — 찾으려는 충돌을 이 도구가 가리는 셈이 됩니다.

4스위치에서 포트 찾기

"이 카메라가 몇 번 포트인가"를 랙 앞에서 선 뽑아가며 찾지 않아도 됩니다. 스위치가 알고 있습니다.

  1. 스위치 → 스위치 조회스위치 IP와 읽기 커뮤니티 문자열을 넣습니다.
  2. 조회를 누른다스위치의 MAC 표를 읽어서 목록의 장비마다 어느 스위치 몇 번 포트인지 붙입니다.

목록의 스위치 포트 칸에 이렇게 나옵니다.

보이는 것뜻
SW-3F   Gi1/0/12   1G3층 스위치 12번 포트, 1기가로 붙음
SW-3F   Gi1/0/12   100M다른 포트보다 느림 — 랜선 의심
SW-3F   Gi1/0/12   1G½반이중 — 6번 항목을 보십시오
SNMP는 대역을 넘습니다

충돌 스캔과 달리 스위치 조회는 UDP 161로 하기 때문에 라우터 너머 스위치도 읽힙니다. 다른 층 스위치 IP만 알면 됩니다.

스위치 → 스위치 포트(Ctrl+P)를 열면 스위치 앞판이 그대로 그려집니다. 실물처럼 홀수는 윗줄, 짝수는 아랫줄입니다.

  • 스위치 관리 포트 — 잠그면 SNMP가 안 닿아 현장에 다시 가야 합니다
  • 장비가 2대 이상 보이는 포트(업링크) — 잠그면 그 아래가 통째로 내려갑니다

잠그거나 풀 때

쓰기 커뮤니티 문자열이 따로 필요합니다. 읽기용으로는 안 됩니다. 쓴 값은 반드시 되읽어서 확인하기 때문에 1~3초 걸립니다 — 정상입니다.

풀어도 통신은 바로 안 살아납니다

랜선 양끝이 속도를 다시 맞추는 데 2~3초, 그다음 스위치가 루프를 확인하는 동안(STP) 최대 30초 더 걸립니다. 그동안 링크 LED는 켜져 있는데 데이터만 안 흐릅니다.

장비가 안 올라와도 30초까지는 정상입니다. 이 도구가 링크를 지켜보면서 알려줍니다. 그 사이에 멀쩡한 포트를 다시 만지지 마십시오.

줄이려면 스위치 설정에서 끝단 포트만 Fast Link를 켜면 2~3초로 줄어듭니다. Cisco CBS220 기준 Spanning Tree → STP Interface Settings → Fast Link: Enable.

업링크 포트에는 Fast Link를 절대 켜지 마십시오

루프가 즉시 돌고 현장 전체가 내려갑니다. 같은 화면의 BPDU Guard를 함께 켜두면 보험이 됩니다.

PoE

급전 중인 포트는 전원을 껐다 켤 수 있습니다. 껐다 켜기는 언제나 한 동작이라 몇 초 뒤 저절로 돌아옵니다. 끈 채로 두려면 전원 끊기를 쓰십시오.

6눈으로 못 찾는 고장 둘

이 도구를 만든 진짜 이유입니다. 둘 다 링크는 멀쩡히 붙어 있고 핑도 갑니다.

① 속도 저하 — "예전엔 1G였는데 지금 100M"

기가는 8가닥을 다 씁니다. 한 가닥만 헐거워져도 링크는 안 끊기고 조용히 100M로 내려앉습니다. 화면이 끊긴다는 신고가 들어와도 눈으로는 절대 못 찾습니다.

이 도구는 포트마다 여태 본 최고 속도를 기억합니다. 그보다 떨어지면 빨갛게 뜨고, 언제 그 속도였는지 날짜까지 알려줍니다.

조치 — 랜선 양끝을 다시 성단하십시오.

일부러 100M 장비를 물려둔 포트라면

포트를 고르고 "이 속도가 정상입니다"를 누르십시오. 다음부터 그 포트는 빨갛게 안 나옵니다. 안 그러면 영원히 빨간 채로 남고, 사람은 곧 빨간색 전체를 무시하게 됩니다.

② 반이중 — "1G로 뜨는데 느리다"

제일 안 잡히는 고장입니다. 속도 칸은 1G로 멀쩡합니다. 그런데 파일 하나 옮기는 데 몇 분이 걸립니다.

원인 — 양끝 중 한쪽만 속도·듀플렉스를 손으로 박아두면, 반대쪽은 협상할 상대가 없어서 규칙대로 반이중으로 내려앉습니다. 반이중 쪽은 늦은 충돌이 나고 전이중 쪽은 깨진 프레임을 봅니다. 둘 다 링크는 안 끊습니다.

이 도구는 ½ 로 표시합니다. 목록의 속도 옆, 앞판 칸 오른쪽 아래, 상세 설명 세 군데에 나옵니다.

여기서 랜선부터 뜯으면 안 됩니다

반이중은 설정 문제입니다. 성단을 두 번 해도 안 고쳐집니다. 양쪽 다 자동(auto)으로 맞추십시오.

늦은 충돌 횟수가 같이 나오면 그건 짐작이 아니라 지금 프레임이 깨지고 있다는 증거입니다.

듀플렉스를 안 알려주는 스위치도 있습니다

그런 스위치는 아무 표시도 안 나오고, 리포트에 '이중 미확인'이라고 적힙니다. 표시가 없는 것이 "확인했고 정상"이라는 뜻은 아닙니다.

9안 될 때

증상원인과 조치
스캔해도 아무것도 안 나온다 Npcap이 없거나 관리자 권한이 아닙니다. 프로그램을 끄고 관리자 권한으로 다시 실행하십시오. 그래도 안 되면 npcap.com에서 Npcap을 설치하십시오.
내 PC가 목록에 없다 있어야 정상입니다. ARP는 자기 외침을 자기가 못 듣기 때문에 따로 넣어줍니다. 안 보이면 랜카드를 잘못 고른 것입니다.
IP가 169.254.x.x 다 DHCP를 못 받았다는 뜻입니다. 사실상 망에 안 붙은 상태입니다. 랜선과 DHCP 서버를 먼저 확인하십시오.
스위치 조회가 안 된다 커뮤니티 문자열이 틀렸거나, 스위치가 SNMP를 안 켰거나, 방화벽이 UDP 161을 막았습니다. 진단 줄이 로그에 나오면 그걸 보십시오 — dot1q·dot1d가 전부 0이면 그 스위치는 MAC 표를 SNMP로 안 내주는 것이라 고칠 수 없습니다.
잠갔는데 스위치가 답이 없다 다시 누르지 마십시오. 잠금이 먹혀서 관리 경로가 끊겼을 수 있습니다. 스위치 화면에서 직접 확인하십시오.
포트를 풀었는데 장비가 안 올라온다 30초까지는 정상입니다(STP). 5번 항목을 보십시오.
빈 IP 목록이 안 나온다 스캔이 끝까지 안 갔다는 뜻입니다. 일부러 안 주는 것입니다. 대역을 다시 스캔하십시오.
실행할 때 파란 경고창이 뜬다 코드 서명이 없어서 그렇습니다. 악성 여부와 무관합니다. 추가 정보 → 실행을 누르십시오.
창 아래 '작업 로그'를 먼저 보십시오

거절당한 이유는 거기 다 적힙니다. 창이 열려 있을 때는 그 창 안에도 같은 내용이 나옵니다.

1Before you start

Two things must be in place before a scan will run.

RequirementHow to check
Administrator rights The program always runs elevated. Click Yes on the prompt at launch. Static ARP pinning and raw packet transmission both require it.
Npcap driver The installer points you to the download if it is missing. You can also get it from npcap.com. Without Npcap, scanning does not work at all.

What to do on the first screen

  1. Check the adapterThe card you are currently using for network access is picked automatically. If you plugged into the site network separately, choose that card from the list.
  2. Check the rangeThe chosen card's range fills in by itself — something like 192.168.0.0/24. Edit it to sweep a different range.
  3. Scan rangeThe sweep runs three passes. One silent reply is not treated as "nothing there".

2What this tool cannot do

Read this first. Trusting the tool where it should not be trusted is how sites get broken.

Silent does not mean free

A powered-off device is also silent. The free-IP list means "no reply was heard", not "definitely unused". Be especially careful on sites where equipment is switched off overnight.

Nothing is visible past a router

Conflict detection uses ARP, and ARP only travels inside one broadcast domain (layer 2). The moment you cross a router, you see nothing. Sweeping a large site from a single point is not possible this way — you have to plug into each range.

One exception: switch queries (SNMP) do cross subnets. If you know another floor's switch IP, you can read its ports from here.

An unfinished scan gives you no free-IP list

If the sweep is stopped or fails, the tool refuses to produce the list at all and tells you why. Handing over a warning together with a list does not work — people read the list.

On a first visit there is no "no speed drop"

Speed comparison needs an earlier reading. With nothing to compare against, the report says "first record". That means "not known yet", not "checked and fine".

3Clearing IP conflicts

CCTV and AV gear ships with the same factory IP. Put eight cameras on one switch and all eight insist they are the same address. An ordinary scanner sees only one of them — Windows keeps a single MAC per IP in its ARP table.

This tool sees all of them. Conflicting rows are marked in red with a 4 devices badge. Click the row to expand it.

Sorting them out without touching a cable

  1. Expand the conflicting rowEvery device sharing that IP is listed by MAC.
  2. Right-click one → Isolate this deviceThat pins the IP to that one MAC (static ARP). From now on, connecting to that IP reaches only that device.
  3. Open its web page and change the IPWith the device isolated, open its web interface and set a new address. Pick the new one from Free IPs (Ctrl+F).
  4. Release the isolationRight-click → Release. Move on to the next device.
Do not close the program with an isolation still active

Static ARP entries stay on the PC. Next launch, the tool offers to clear "N leftover isolations" — accept it. Left in place, that IP keeps showing a single device: the tool would be hiding the very conflict you came to find.

4Finding a device's switch port

You do not have to pull cables at the rack to answer "which port is this camera on". The switch already knows.

  1. Switch → Query switchEnter the switch IP and the read community string.
  2. Press QueryThe tool reads the switch's MAC table and tags every device in the list with which switch and which port it sits on.

The Switch port column then shows this.

What you seeMeaning

5Locking and unlocking ports

Switch → Switch ports (Ctrl+P) draws the switch faceplate as it really is — odd numbers on the top row, even below.

ColourMeaning
GreenIn use
RedSpeed drop, or half duplex (½)
White, outline onlyUnused port
Red outline, ✕Locked port
Yellow bar underneathPoE power being delivered
Dashed outlineCannot be locked
Three kinds of port are blocked from locking on purpose
  • The port this computer is on — locking it cuts your own connection
  • The switch management port — locking it kills SNMP and you have to drive back to site
  • Any port showing two or more devices (an uplink) — locking it takes everything below it down

Locking or unlocking

This needs a separate write community string; the read-only one will not do. Every written value is read back to confirm it, which is why the operation takes 1–3 seconds. That is intended.

Unlocking does not bring traffic back immediately

The two ends renegotiate speed for 2–3 seconds, then the switch checks for loops (STP) for up to 30 seconds more. During that time the link LED is lit but no data flows.

A device not coming back within 30 seconds is normal. The tool watches the link and tells you. Do not go poking at a healthy port while that is happening.

To shorten it, enable Fast Link on edge ports only: on a Cisco CBS220 that is Spanning Tree → STP Interface Settings → Fast Link: Enable, which brings it down to 2–3 seconds.

Never enable Fast Link on an uplink port

A loop forms instantly and the whole site goes down. Turn on BPDU Guard on the same screen as insurance.

PoE

Ports delivering power can be power-cycled. A cycle is always a single action — power returns by itself a few seconds later. To leave a port unpowered, use Cut power instead.

6Two faults you cannot see

This is the real reason the tool exists. In both cases the link is up and ping works.

1. Speed drop — "it used to be 1G, now it is 100M"

Gigabit uses all eight wires. One loose strand and the link does not drop — it quietly settles at 100M. Someone reports stuttering video and there is nothing to see with your eyes.

The tool remembers the best speed ever seen on each port. Fall below it and the port turns red, with the date that speed was last recorded.

What to do — re-terminate both ends of the cable.

If a 100M device belongs on that port

Select the port and press "This speed is normal". It stops being flagged. Otherwise it stays red forever, and people soon start ignoring red altogether.

2. Half duplex — "it says 1G but it crawls"

The hardest fault to catch. The speed column reads a healthy 1G — yet copying one file takes minutes.

Cause — if only one end has speed and duplex hard-coded, the other end has nothing to negotiate with and, by the rules, falls back to half duplex. The half-duplex side logs late collisions; the full-duplex side sees malformed frames. Neither side drops the link.

The tool marks it with ½, in three places: next to the speed in the device list, in the corner of the faceplate tile, and in the detail panel.

Do not start by re-terminating the cable

Half duplex is a configuration problem. You can re-terminate twice and it will not help. Set both ends to auto.

If a late-collision count is shown alongside, that is not a guess — frames are being lost right now.

Some switches do not report duplex at all

Those show nothing, and the report says "duplex not read". The absence of a mark is not the same as "checked and fine".

My own PC is not in the list It should be. ARP cannot hear its own call, so the tool adds the local machine deliberately. If it is missing, you picked the wrong adapter.
